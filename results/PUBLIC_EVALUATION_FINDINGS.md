# 本轮评测结论与课题调整

2026-09-21；对应四个固定先导子集、425 题、1,700 次正式请求。完整数字和协议见 [总报告](PUBLIC_BENCHMARK_REPORT.md)。

本轮证实当前短答案策略能够大幅减少生成过程，但没有证实“普遍保持长链推理准确率”，也没有显示出超过普通短答案的独立优势。建议保留 OmniJev 作为系统研究原型，调整研究主张。

## 三项原始目标的结果

- **快速：支持相对本轮推理基线的速度收益。** 四组的中位响应时间之比分别为约 13.6、10.0、8.7、6.8 倍。普通短答案具有相近延迟。八帧视频的 OmniJev 中位耗时仍为 2.98 秒，不能据此声称满足亚秒控制或高频实时决策。
- **低 token：支持。** OmniJev 平均生成 3 tokens，而推理组为约 719–2,419 tokens。计入多模态输入后，四组总 token 节省分别为 85.79%、66.16%、71.80%、51.26%。这是 API 用量，不是等比例的 FLOPs 或能耗下降。
- **准确率一致：尚未证实。** MMBench、MMAD 和视频小子集的总体正确率相同，但并非逐题决策相同；相对于推理组的有效答案一致率分别为 93.33%、86.67%、85.00%。MMStar 正确率从推理组的 72.33% 降至 66.67%，差 5.67 个百分点。四组均未达到本轮保守区间下的 2pp 非劣标准。

MMStar 的数学子集是具体反例：短答案答对 27/50，推理组答对 45/50。类别分析是在结果出来后做的解释，不能直接变成利用测试集设计并验证路由策略的依据。

## 对“通用模型足矣”的回应

本轮结果支持一个有限结论：**当前仓库的固定选项短标签路径，可以由同一通用模型的普通短答案调用复现其准确率与 token 用量。** 四组均没有配对正确率收益，延迟也接近。请求 logprobs 提供了候选分数接口，但本轮没有证明这些分数能改善拒答、路由或任务成功率。

因此，当前实现不足以支持“独立的新模型范式”这一论文主张。这不等于否定未公开的 Jev 内部机制，也不意味着动态多模态决策系统没有研究价值。

## 建议的课题定位

建议调整为：**免训练、时限约束下的多模态选择性推理与决策系统**。

1. 保留短答案快速路径；研究何时升级到长链推理、何时拒答。候选分数需在独立开发集校准，不能直接将 softmax 分数当作正确概率。
2. 面向连续输入研究事件触发感知、状态记忆和失效检测：只有环境变化或证据不足时重新处理媒体。相应收益需要新的连续场景实验验证。
3. 用普通短答案、固定频率感知和固定推理预算作为强基线，在相同错误率或相同时限下比较成功率与成本。阈值、规则和缓存策略先在开发集确定，再冻结到新测试集；同时报告最差场景与尾延迟。

本轮五秒期限内的正确率说明该方向值得探索：MMStar 为 66.67% 对 9.00%，视频子集为 85.00% 对 5.00%（OmniJev 对推理组）。但普通短答案也达到相同快速路径成绩，因此后续必须证明调度与状态管理相对普通短答案的增量收益。

## 解释限制

本轮只测本机 Nemotron 3 Nano Omni Q4_K_M，未训练模型；不是 Qwen 与 Nemotron 的模型间比较。使用 Bionic medium，实测约 8k 思考预算、总输出上限 20,480；47 次推理响应检测到内部预算强制回答提示，其中 1 次还达到总输出上限。保留全部请求，无接口错误。

服务采用自然缓存，主实验经历协议校准，不能视作预注册确认性实验。视频是经过因果校验的预抽帧问答，没有原生音频或闭环动作执行。四个公开子集不是官方全量榜单，样本量有限，MMStar 与 MMBench 还可能共享来源；不能把它们当作完全独立的泛化证据。
