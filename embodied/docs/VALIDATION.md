# Experimental results and validation scope

Xingzhi can now run real model calls, physical interaction, and visual input. Below are results separated by input, control method, and model to help determine what each result indicates.

## Jev hierarchical XYZ trial run

Two local development episodes used `jev-1.13.0`, transfer seed 7, and simulated coordinates and contacts as input: 89 / 88 steps, 178 / 176 requests, and 72.43 / 79.71 seconds, respectively, ultimately meeting the physics success criteria. Both lost their grasp during lowering, dropping the block into the tray, and then opened the gripper and withdrew. This is not yet stable, precise placement. No images were sent to Jev, and no rule-based action substitution was used.

## Incremental visual planning

This group uses GPT-6 Astra, dual-camera raw images, transfer task seed 7. The model selects XYZ short steps round by round, without receiving object or target coordinates.

| Round | Result | Action / API call |
| --- | --- | --- |
| Normal transfer | Complete grasp, placement, and withdrawal | 32 / 32 |
| Tray moved during the episode | Regrasped after losing contact, adjusted to the new target, and completed the task | 43 / 43 |
| Initial goal description incomplete | After placing in tray, withdrawal height insufficient, stopped | 32 / 32 |
| Two API failures | Request timeout, not completed | 2 / 3, 0 / 1 |

After initial failure, added final withdrawal height requirement; goal conditions before and after revision not counted as same setting. Only a few development rounds in same scenario, not merged for success rate calculation.

Same short-step interface also has a hand-written rule comparison, using simulated coordinates, completing tray move in 40 steps, model calls 0. It is not strictly input-matched with image-input model rounds.

## Functional check

Incremental planning and camera configuration version passed **401 Python tests, 27 browser tests**, frontend build passed; [corresponding CI](https://github.com/FBddcz/embodied-jev/actions/runs/35503314655) also passed.

Tests cover action execution, safety checks, pause and stop, input sanitization, image request format, camera selection, caching, perturbation, trajectory replay, and interface operation. Automated model and browser camera use simulated responses; real pixel changes, model actions and physical results checked by above independent experiments.

## What to note when reading these results?

- **Success is success in simulation.** Objects must be stable on target, gripper released, end-effector withdrawn; real robot not yet verified.
- **Replay is not reasoning timing.** Animation and timeline omit waiting; delay must be seen from exported actual time.
- **Different settings cannot be directly ranked.** Skills and short-steps, coordinates and images, models and rules should be reported separately.
- **Small samples cannot represent generalization.** Lack of paired experiments with different camera combinations, image removal, unknown objects and untested layouts.
- **Reasonable text explanation is not proof.** Must compare input image, selected action and post-execution change.
